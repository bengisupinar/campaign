Why `backend/` + `frontend/` rather than a Go module at the root:
- It cleanly separates the two toolchains.
- `go ./...` never walks `node_modules`.

#### Key design choices and trade-offs

1. **`main` → `run(ctx, getenv, stdout) error`.**
   - `main` only sets up `signal.NotifyContext(SIGINT, SIGTERM)` and calls `os.Exit(1)` on error.
   - Dependencies are injected, so `run` and `config.Load` can be tested without touching process globals.
2. **Config:** environment variables only (12-factor), parsed into a typed struct, with every error collected via `errors.Join`, failing fast at startup.
   - The binary never reads `.env`.
   - The Makefile loads `.env` for host runs (`-include .env` + `export`), so overrides such as `make run LOG_FORMAT=json` still win.
   - Compose sets `environment:` explicitly per service.
   - Variables:
     - `DATABASE_URL`: required.
     - `HTTP_ADDR`: default `:8080`.
     - `LOG_LEVEL`: default `info`.
     - `LOG_FORMAT`: `json` or `text`, default `json`. `.env.example` sets `text`.
   - The DB URL is never logged.
3. **Postgres:** `pgxpool.New` plus a `Ping` bounded to 5s at startup.
   - If the DB is unreachable at boot, the API exits non-zero with a clear message.
   - Compose `depends_on` ordering makes this a non-issue in containers.
   - Pool settings use pgx defaults, overridable through URL params (`pool_max_conns`). There are no extra env vars for them.
4. **Migrations:** goose v3, SQL files embedded with `embed`, run by a **separate `cmd/migrate` binary**.
   - It uses the goose `Provider` API with a Postgres advisory-lock session locker and `pgx/v5/stdlib` for `*sql.DB`.
   - In Compose, a one-shot `migrate` service runs before `api` (`service_completed_successfully`).
   - Trade-off: this is one more binary than "migrate on startup". In exchange, the API needs no DDL privileges, and `down`/`status` exist for development.
   - `00001_baseline.sql` is a deliberate no-op (`SELECT 1`). It proves the pipeline end to end; `//go:embed` needs at least one file, and goose errors on an empty set.
5. **HTTP server:**
   - `ReadHeaderTimeout` 5s, `ReadTimeout` 15s, `WriteTimeout` 30s, `IdleTimeout` 60s.
   - Future SSE handlers lift the write deadline per request with `http.ResponseController`.
   - `BaseContext` is **not** tied to the signal context, so in-flight requests aren't cancelled the moment SIGTERM arrives.
6. **Health checks:**
   - `GET /healthz` is liveness. It always returns 200 and checks no dependencies, so a DB outage doesn't cause restart loops.
   - `GET /readyz` is readiness. It pings Postgres within a 2s timeout and returns `200 {"status":"ok","checks":{"postgres":"ok"}}` or `503`. Error details are logged, never returned.
   - Checks are a `map[string]func(context.Context) error`; `pool.Ping` is passed as a method value. No interface is needed.
7. **Graceful shutdown order:** signal → `srv.Shutdown` → `pool.Close()` → exit 0.
   - `srv.Shutdown` closes the listeners and waits for in-flight requests, with a 10s timeout derived via `context.WithoutCancel`.
   - Compose `stop_grace_period: 15s` is longer than the 10s timeout.

#### Key design choices

1. **`main` → `run(ctx, …) error`.** `main` only sets up `signal.NotifyContext(SIGINT, SIGTERM)` and calls `os.Exit(1)` on error. Dependencies are passed in explicitly, with no package-level globals.
2. **Config:** caarlos0/env reads struct tags with defaults and `required`.
   - Every error is reported at once, failing fast.
   - The binary never reads `.env`. The Makefile loads it for host runs, and Compose sets `environment:` explicitly.
   - Variables:
     - `DATABASE_URL`: required.
     - `HTTP_ADDR`: default `:8080`.
     - `LOG_LEVEL`: default `info`.
     - `LOG_FORMAT`: `json` or `text`, default `json`.
   - The DSN is never logged.
   - Tests inject an env map instead of setting process variables.
3. **Database:** GORM with the postgres driver (pgx underneath).
   - Explicit pool limits as constants: max open/idle connections and connection lifetime.
   - A 5s ping at startup. If it fails, the process exits non-zero with a clear message.
   - GORM's logger is routed to slog (warnings, errors, slow queries).
4. **Migrations:** goose with embedded SQL files, applied **on API startup before the listener opens**.
   - A Postgres advisory lock keeps concurrent starts safe.
   - Trade-off: the API needs DDL rights. That's fine here, and the reason is noted in DECISIONS.md.
   - Development commands use the goose CLI through `go run github.com/pressly/goose/v3/cmd/goose@<version from go.mod>`. No global install and no extra code.

## Key design choices

1. **`main` → `run(ctx, …) error`.** `main` only sets up `signal.NotifyContext(SIGINT, SIGTERM)` and calls `os.Exit(1)` on error. Dependencies are passed in explicitly, with no package-level globals.
2. **Config:** caarlos0/env reads struct tags with defaults and `required`.
   - Every error is reported at once, failing fast.
   - The binary never reads `.env`. The Makefile loads it for host runs, and Compose sets `environment:` explicitly.
   - Variables:
     - `DATABASE_URL`: required.
     - `HTTP_ADDR`: default `:8080`.
     - `LOG_LEVEL`: default `info`.
     - `LOG_FORMAT`: `json` or `text`, default `json`.
   - The DSN is never logged.
   - Tests inject an env map instead of setting process variables.
3. **Database:** GORM with the postgres driver (pgx underneath).
   - Explicit pool limits as constants: max open/idle connections and connection lifetime.
   - A 5s ping at startup. If it fails, the process exits non-zero with a clear message.
   - GORM's logger is routed to slog (warnings, errors, slow queries).
4. **Migrations:** goose with embedded SQL files, applied **on API startup before the listener opens**.
   - A Postgres advisory lock keeps concurrent starts safe.
   - Trade-off: the API needs DDL rights. That's fine here, and the reason is noted in DECISIONS.md.
   - Development commands use the goose CLI through `go run github.com/pressly/goose/v3/cmd/goose@<version from go.mod>`. No global install and no extra code.
   - `00001_baseline.sql` is a deliberate no-op (`SELECT 1`). It proves the pipeline end to end; `//go:embed` needs at least one file.
5. **HTTP:** chi on `net/http`, so handlers stay plain `http.HandlerFunc` and can be tested with `httptest`.
   - Server timeouts: `ReadHeaderTimeout` 5s, `ReadTimeout` 15s, `WriteTimeout` 30s, `IdleTimeout` 60s. Future SSE handlers lift the write deadline per request.
   - Middleware:
     - chi's `RequestID`.
     - A small slog access log: request_id, method, path, status, bytes, duration.
     - A recoverer that logs panics as structured JSON. chi's own recoverer prints unstructured stack traces.
   - `BaseContext` is not tied to the signal context.
6. **Health:**
   - `GET /healthz` is liveness: always 200, no dependency checks, so a DB outage doesn't cause restart loops.
   - `GET /readyz` is readiness: a DB ping within 2s, returning `200 {"status":"ok","checks":{"postgres":"ok"}}` or `503`. Error details are logged, never returned.
7. **Graceful shutdown:** signal → `srv.Shutdown` (waits for in-flight requests, 10s timeout) → close the DB → exit 0.
   - Compose `stop_grace_period` is 15s.
   - No readiness drain flag, because it does nothing without a load balancer's pre-stop delay.
8. **Docker:**
   - Backend image: `golang:1.27-alpine` with BuildKit caches → `alpine:3.24`, running as a **non-root** user. Busybox `wget` serves the healthcheck.
   - It builds all `./cmd/...` binaries into `/app/`.
   - Postgres 18: the volume is mounted at `/var/lib/postgresql`, because PG 18 images moved `PGDATA`. Its healthcheck is `pg_isready`.
   - The API healthcheck hits `/readyz`. `web` waits for `api: service_healthy`.
   - Host ports are configurable: Postgres `5432`, API `8080`, web `3000`.
9. **Frontend:**
   - Dev: Vite on 5173 proxies `/api` and `/readyz` to `localhost:8080`.
   - Compose: `node:26-alpine` builds the app, and **nginx-unprivileged** serves the SPA (`try_files … /index.html`) and proxies `/api/` and `/readyz` to `api:8080`.
   - Compose: nginx re-resolves `api` through Docker DNS, so recreating the API container doesn't leave stale-IP 502s.
   - `frontend/.dockerignore` excludes the host `node_modules` and `dist`; macOS binaries must not reach the Linux build.
   - `App.vue` renders an `ApiStatus` component showing ready, not ready or unreachable. It has one Vitest test with `fetch` mocked.
   - No Router, Pinia or UI library yet. They come with the first real screen.
   - The scaffolded `frontend/.gitignore` is removed; the root rules cover it.

**Left out on purpose:** Redis (deferred, agreed), CORS (same-origin through proxies), hot reload, testcontainers, CI, a readiness drain flag, a UI component library, Router/Pinia.

**Designed for later, not built:**
- `seed`: a one-shot Compose service using the backend image, after `api: service_healthy`, idempotent.
- `mockprovider`: a separate service or in-process, decided in the delivery phase.
- Mock LLM used when no API key is set.
- Queue choice (Redis Streams vs a Postgres-backed queue).
- SSE through nginx (`proxy_buffering off`).
